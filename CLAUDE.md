# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

TriSync is an Expo (SDK 54, React Native 0.81, React 19, new architecture enabled) app for planning race training (triathlon-style workouts: Swim, Bike, Run, Brick, Strength, Rest). It targets iOS, Android and web. Code is plain JavaScript (`.js`), even though `tsconfig.json` exists.

## Commands

- `npm start` — Expo dev server (`npm run ios` / `npm run android` / `npm run web` for a specific platform)
- `npx expo start -c` — restart with a cleared Metro cache; needed after changing `babel.config.js` or `tamagui.config.js`
- `npx expo install <pkg>` — add Expo-managed deps so versions match SDK 54

There are no build-time secrets. Each user enters their own Strava API app's Client ID and Secret in Settings → Strava, and they're stored on-device (`trisync/strava-keys/v1`). This makes every copy of the app its own instance. Never reintroduce `EXPO_PUBLIC_*` keys: Expo inlines them into the bundle.

- Production web build, as deployed: `EXPO_NO_DOTENV=1 EXPO_BASE_URL=/trisync npx expo export -p web --output-dir dist`

There is no test runner, linter, or formatter configured.

**Deploy:** `.github/workflows/deploy-web.yml` publishes the web build to GitHub Pages on every push to `master`. `app.config.js` applies `experiments.baseUrl` only when `EXPO_BASE_URL` is set, so local dev still serves from `/`. `public/` holds the PWA files: a customised `index.html` with manifest and home-screen tags, `manifest.json`, the icons, and a network-first `sw.js`. `index.js` registers the service worker on web in production only. `src/pwa/installPrompt.js` is imported early in `index.js` so it catches Chrome's one-time `beforeinstallprompt` event before React mounts. The ☰ menu's "Install TriSync" item replays that prompt, or opens `InstallModal` with per-platform steps (iOS never fires the event). The item is hidden when the app is already running installed. Paths in `public/` must stay relative, so they work under the `/trisync/` base path.

## Architecture

- **Entry:** `index.js` registers `App.js` and loads `app.web.css` only on web (it makes `#root` a full-height flex column so React Native Web scroll views work). `global.css` is not currently imported.
- **App shell (`App.js`):** `ThemeProvider` wraps everything. Once the Plus Jakarta Sans fonts load, it renders `TamaguiProvider` → `StravaProvider` → `TrainingProvider` → `NavigationContainer` with a bottom tab navigator holding two screens: `TodaysActivitiesScreen` ("Today") and `TrainingCalendarScreen` ("Calendar"). `HeaderLogo` (the tri glyph, tinted with `t.text`) is rendered as `headerLeft` and `TrainingHeaderMenu` as `headerRight` on every tab.
- **State (`src/training/TrainingContext.js`):** a single React context, accessed with `useTraining()`, holds `planRange` (`{ start, raceDate, raceName, weeks }`, or `null` when no plan exists) and the `workouts` array, plus the actions (`createPlan`, `startEditingPlan`/`cancelEditingPlan`, `addWorkout`, `updateWorkout`, `deleteWorkout`). `planRange` and `workouts` are saved to AsyncStorage (`trisync/training/v1`; localStorage on web). Data saved under the old `oneplan/*` keys (from before the OnePlan → TriSync rename) is migrated on load. The provider renders a blank screen until the saved data has loaded, so the empty initial state never overwrites it. `createPlan` returns `{ error }` for validation failures. It clamps the plan start to today, but an edited plan that has already begun keeps its original start. "Edit plan" sets `editingPlan` and navigates to the Calendar tab, which shows the setup form pre-filled; `planRange` stays intact until the user saves, or until they cancel.
- **Shared module (`src/training/trainingUtils.js`):** contains date helpers, workout types and icons, `statusFor()`, the `FONT_*` Plus Jakarta Sans family names, and `notesInputStyle(theme)`.
- **Theme (`src/theme/`):** `themes.js` defines the Dark palette (matching the Strava graphic), the Light palette and the Discord-style `GRADIENTS` presets. Gradient themes are built on a dark or light base, with translucent "glass" surfaces that are blurred on web. `ThemeContext.js` saves the user's choice (`trisync/appearance/v1`) and provides `useTheme()`, which returns colour tokens (`t.bg`, `t.surface`, `t.text`, `t.status.done`, ...), and `useAppearance()`, used by `SettingsModal` (opened from the ☰ menu). `AppBackground` draws the gradient behind the whole navigator with react-native-svg, so the header, scenes and tab bar are transparent in gradient themes. Components call `const t = useTheme()` and never hard-code colours. Menus and dialogs use `t.surfaceSolid`, because `t.surface` is see-through in gradient themes.
- **Shared UI (`src/training/WorkoutRow.js`):** exports `Pill`, `WorkoutRow` and `AddWorkoutForm`, which both screens reuse.
- **Strava (`src/strava/`):** `stravaApi.js` makes plain `fetch` calls to the Strava API (no backend). `StravaContext.js` keeps the user's API keys and OAuth session in AsyncStorage (`trisync/strava-keys/v1`, `trisync/strava/v1`), refreshes expired tokens, and exposes `syncWorkout`. The keys are passed into every `stravaApi` auth call. Changing the keys drops the session, because tokens belong to the app that issued them. `callbackDomain()` gives the value users must set as the Strava app's Authorization Callback Domain: `shahshachi1.github.io` on web (`WEB_CALLBACK_DOMAIN`; Strava always allows `localhost` too, so local dev works with the same setting). Settings explains Strava's per-app rate limit (100 requests every 15 minutes, 1,000 a day; a sync uses about 3), and a 429 response becomes a plain "limit reached" message. On web, login is a full-page redirect back to the app with `?code=`, which `StravaProvider` picks up on mount. On native it uses `expo-web-browser` with the `trisync://` scheme; that path is untested. When a workout is marked Done or Partial, `WorkoutRow` matches it to the Strava activity with the same date and sport. If there are zero or several candidates, the user picks one. Activities already linked to another workout are never offered again. The matched activity is stored on the workout as `stravaActivityId`. Its name becomes `TriSync: <workout title>`, falling back to Strava's own name. Its description is replaced with the workout notes; if the notes are empty, the description is left alone. A brick is entered as two Brick workouts on the same day, one per leg, and their order in the list sets the description prefix `Brick Part 1: ` / `Brick Part 2: `.
- **Activity graphic:** `activityGraphic.js` builds a 1080×1080 dark-card SVG string from the Strava activity's `laps`, or `splits_metric` if there's only one lap. It shows a headline distance (or time), the workout title and a status badge (green for Done, orange for Partial). The bars are about 32 slim bars, divided between laps by duration. Hard laps glow in the accent colour unless the effort was steady (speeds within 10%), in which case every bar lights. A progress line shows the share of time in hard laps, followed by a summary with highlighted numbers and a `TriSync · <plan week>` footer. `ActivityGraphicModal` previews the SVG and saves it: on web it draws it to a canvas and downloads a PNG; on native it uses `react-native-view-shot` and `expo-sharing` (untested). Strava's public API can't attach photos (partner apps only), so the user uploads the image to Strava manually.
- **Backup (`src/backup/backup.js`, web only):** Settings → Backup exports the training data, appearance and Strava API keys as a `trisync-backup-<date>.json` file, and imports one (replacing this device's data, then reloading). The Strava login session is deliberately left out, so users reconnect after an import. There is no server, so this is the only way to move data between browsers, devices, or Safari and an iPhone home-screen install. `index.js` also asks for persistent storage.
- **No zoom (web):** the viewport tag (`maximum-scale=1, user-scalable=no`) and `touch-action: pan-x pan-y` in `public/index.html`, plus `src/pwa/noZoom.js` (iOS pinch gestures, ctrl/⌘ + wheel or +/−/0), keep every screen at a fixed scale.
- `src/components/DashboardHeaderMenu.js` is unused. It is a leftover light/dark toggle.

## Conventions and gotchas

- **Dates:** dates are stored and compared as ISO `YYYY-MM-DD` strings (string comparison is used for ordering, e.g. in `statusFor`). User input and display use `DD-MM-YYYY`; convert with `displayToIso` and `isoToDisplay`. Helpers parse with a `T00:00:00` suffix (local midnight) and format back with `toIsoDate()`, which uses the local time zone. Never use `toISOString().slice(0, 10)`: it is UTC and shifts the date by a day in many time zones.
- **Workout status:** the stored `status` is `'pending' | 'done' | 'partial'`. The displayed status comes from `statusFor(workout, today)`, which turns pending workouts into `'missed'` (past) or `'upcoming'`. In the calendar, a day with several workouts shows the worst status, ranked by `STATUS_PRIORITY`.
- **Styling:** styling mixes Tamagui layout primitives (`YStack`, `XStack`, `Card`, `Paragraph`, `$` tokens) with RN `Text`/`Pressable` and inline styles that use the tokens from `trainingUtils`. Popovers come from `@tamagui/popover`. Icons come from `@expo/vector-icons` (Ionicons).
- **Strava token requests** must be form-encoded, because `oauth/token` doesn't answer CORS preflights; a JSON body fails in the browser.
- **Tamagui shorthands:** the app uses `@tamagui/config/v5`, whose shorthands differ from older Tamagui (`items`/`justify`, not `ai`/`jc`; `f` doesn't exist). Unknown shorthands are silently ignored, so use full prop names (`alignItems`, `justifyContent`, `flex`). `p`, `px`, `mt`, `mb` and `gap` are fine.
- **Inactive tabs on web:** `index.js` calls `enableScreens(true)` on web so inactive tab screens get `display: none`. Without it, bottom tabs just stack screens and rely on opaque backgrounds, so they show through each other in gradient themes.
- **Babel:** `babel.config.js` runs the Tamagui babel plugin and `react-native-reanimated/plugin`; the reanimated plugin must stay last.
